# Migration to 0.12.1

## What changes

- **Terms are written out in full.** Before: an agent could shorten terms in what it
  wrote, for example "L1" for "Layer 1", and the reader had to guess what they meant.
  Now: every request file, doc, agent file, commit message, report, and answer to the
  developer writes the full term. Abbreviations that are standard in the field (API,
  UI, JSON, CI) and names that are spelled that way in code, commands, or ids
  (`REQ-0012`, `E3`) stay as they are. An abbreviation that is not standard, and has
  to appear because the developer, a document, or the code uses it, is written as the
  full term at its first use, with the abbreviation in parentheses, and the full term
  is used after that. The rule is a new item of "Working agreement" in the root
  `AGENTS.md`.

## Steps

1. **Root `AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `working-agreement`, which gets the
   new item. Already done when that block contains the words "Write terms out in
   full".
2. **Existing files.** Change none. Request files, docs, and commit messages written
   before this version keep their abbreviations; the rule applies to text written from
   now on. A request file gets the full terms where a skill rewrites a part of it.

## Check

- The managed block `working-agreement` of the root `AGENTS.md` contains the item that
  starts with "Write terms out in full".
- No request file and no file under `docs/` changed.
