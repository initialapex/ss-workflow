# Migration to 0.5.0

## What changes

- **Pushing is a setting.** Before: the agent pushed its branches after every commit
  whenever a remote existed. Now: `push-policy` in "Workflow settings" decides.
  `auto` is the behavior of before, `ask` asks before the first push of a skill run,
  and `never` leaves every push to the developer. This migration sets `auto`, so
  nothing changes unless the developer picks another value.
- **No remote is a supported setup, by contract.** Before: most steps already skipped
  their push without a remote, but some said "commit and push" without a condition.
  Now: root `AGENTS.md` has a "Remote and pushing" section, and every skill follows
  it. Without a remote, or without a push, a claim holds in this repository only.
- **A protected `develop` is not worked around.** Before: only the spec merge of
  `/ss-workflow:new-req` handled a remote that refuses pushes to `develop`. Now: every
  merge undoes its unpublished local merge and opens a merge request, or stops and
  says what has to be merged, when the remote has no platform for merge requests.
- **Request files record questions and answers.** Before: decisions were dated lines
  in `## Notes`, and open points were an "Open questions" part of the spec. Now: every
  question that changes the request, and the developer's answer, is an entry in a
  `## Q&A` section. A question without an answer has `A: (pending)`, and a request
  becomes `ready` only when no entry is pending. New specs have no "Open questions"
  part.
- **Results say what did not run.** Before: the implementation summary had one line
  for the build. Now: every result lists each check as `passed`, `failed`,
  `did not run`, or `not configured`, and the summary lists what is not done.
- **Changes to agent behavior files are reviewed as behavior.** Before: a change to
  `AGENTS.md`, `CLAUDE.md`, a skill, or a prompt file was reviewed like any other
  file. Now: the request records what an agent did before and what it does after, and
  the developer confirms each item in the Review.
- **`/ss-workflow:check-req` reads the local `develop` when it is ahead of the
  remote.** Before: with a remote it always read `origin/develop`, so a request that
  was approved but not pushed was invisible. Now it sees it, and says that other
  machines do not.

## Steps

1. **Settings** in root `AGENTS.md`, block "Workflow settings":
   - Add `push-policy: auto` on the line after `merge-method:`. `auto` keeps the old
     behavior. Tell the developer about `ask` and `never` (the table is in
     `references/questionnaire.md`, Round 5), and ask whether to keep `auto`. Needs
     the developer's answer.
   - Add an empty `agent-files:` on the line after `verify-command:`.
   - Below the settings table, add the paragraph of the template that explains
     `push-policy` and `agent-files` (it starts with "`push-policy` (`auto`, `ask`,
     or `never`) is explained in"). This text is outside the managed blocks, so show
     it to the developer.
   - Already done when both keys exist.
2. **`remote-platform`**: if `git remote` lists a remote, and `remote-platform` is
   `none`, nothing is wrong: `none` now also stands for a remote without merge
   requests. If `merge-method` is `remote` while `remote-platform` is `none`, set
   `merge-method: local`, after the developer agrees.
3. **Managed blocks**: the upgrade adds the blocks `remote` (root `AGENTS.md`, after
   "Branching model"), `reqs-qa`, and `reqs-results` (`reqs/AGENTS.md`, after "Request
   file format"), and re-renders the others. Nothing to do here.
4. **Request files**: do not rewrite them.
   - Files in `reqs/done/` stay as they are.
   - Open requests get their `## Q&A` section from the skill that next changes the
     file: `/ss-workflow:new-req` for a draft, `/ss-workflow:check-req` and
     `/ss-workflow:review` for a claimed request. The section goes between
     `## Original` and `## Notes`.
   - A draft that still has an "Open questions" part with content: when
     `/ss-workflow:new-req` continues it, each open question becomes a `## Q&A` entry
     with `A: (pending)`, and the part is removed from the spec.
   - Earlier decisions in `## Notes` stay where they are. Do not turn them into
     `## Q&A` entries: nobody recorded the question as it was asked.
5. **Agent behavior files of this project**: ask the developer whether the project has
   files that tell an agent how to behave, outside `AGENTS.md`, `CLAUDE.md`,
   `.claude/`, and skill folders, for example prompt files that the product ships. If
   yes, write their paths into `agent-files`, as glob patterns separated by commas.
   Needs the developer's answer.

## Check

- `push-policy:` in root `AGENTS.md` is `auto`, `ask`, or `never`, and `agent-files:`
  exists.
- Root `AGENTS.md` has the section "Remote and pushing". `reqs/AGENTS.md` has the
  sections "Questions and answers" and "Results and behavior changes", and its request
  file format shows `## Q&A` between `## Original` and `## Notes`.
- `git status --porcelain -- reqs/` shows no changed request file, only
  `reqs/AGENTS.md`.
