# Migration to 0.12.3

## What changes

- **A started hotfix keeps its id.** Before: an id was in use only when a file on
  `develop` or a branch name had it. A started hotfix lives on
  `hotfix/<name>-v<version>`, whose name has no id, and its draft branch is deleted,
  so a new request could get the same id. Now: the request file on each such branch
  counts too. The rule is in "Files" of `reqs/AGENTS.md`.
- **Worktrees of an existing request branch.** Before: "Workspace and projects" in
  the root `AGENTS.md` created every worktree with `-b`, a new branch, although the
  request branch exists since the draft, and a project branch exists when a worktree
  is recreated. Now: the commands use the existing branch, and create one only for a
  hotfix, a `ready` request from before ss-workflow 0.8.0, and a project branch when
  the request starts. The same section now says what `<develop-ref>` and
  `<project develop-ref>` stand for.

## Steps

1. **Root `AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `workspace`. Already done when that
   block contains the words "`<develop-ref>` stands for".
2. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `reqs-files`. Already done when that
   block names `hotfix/<name>-v<version>`.
3. **Request files and branches.** Change none.

## Check

- The block `workspace` of the root `AGENTS.md` contains "`<develop-ref>` stands for".
- The block `reqs-files` of `reqs/AGENTS.md` names `hotfix/<name>-v<version>`.
- No request file changed.
