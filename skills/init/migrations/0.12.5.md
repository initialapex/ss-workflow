# Migration to 0.12.5

## What changes

- **Docs follow the code without being listed.** Before: "File changes" in the spec
  said that a file that is not listed is not changed, so the implementation left a
  doc that describes the changed code as it was (or widened the spec through a
  `## Q&A` entry to change it), and the doc went stale. Now: `/ss-workflow:check-req`
  brings every doc that describes what a listed change changes (`docs/<name>/`,
  `docs/overview.md`, a project README or sample) in line with it, without asking and
  without changing `## Spec`, and names it under "Not in the detailed design" in the
  implementation summary. The design check of `/ss-workflow:review` accepts it there.
  A doc that would need a decision that the spec does not make is still a gap in the
  spec, and the implementation asks.

## Steps

1. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `reqs-spec`. Already done when the
   block `reqs-spec` contains "with one exception: a doc that describes what a listed
   change changes".
2. **Request files and branches.** Change none. A request that is already in review
   keeps its implementation summary as it is.

## Check

- The block `reqs-spec` of `reqs/AGENTS.md` contains "with one exception: a doc that
  describes what a listed change changes".
- No request file changed.
