# Migration to 0.12.0

## What changes

- **Evidence, not guesses.** Before: an agent could state how the existing code
  behaves, or why a problem happens, from what it read or expected, without saying how
  it knew. Now: every such statement rests on evidence that someone else can check (a
  `file:line` at a named commit, the output of a command that ran, a log or a
  measurement, a test result), or is marked as inferred, to trace, to test, or stated
  by the developer. This holds in request files, in reports, and in every answer to
  the developer. The rule is a new item of "Working agreement" in the root
  `AGENTS.md`.
- **A new section `## Evidence` in the request file**, between `## Q&A` and
  `## Notes`. It is the single source of truth for the facts of a request: one entry
  per fact (`E1`, `E2`, ...), with its evidence, a status (`verified`,
  `developer-stated`, `inferred`, `to trace`, `to test`, `failed`), a trace where one
  is needed, the parts of the spec that cite it, and a dated history. `reqs/AGENTS.md`
  gets a section "Evidence" that describes it.
- **Step-by-step traces.** To understand an existing flow, or the root cause of a bug,
  an agent traces it through the code and writes a simulated call stack, with the
  values of the variables that decide each step. A trace is required for the root
  cause of every `fix` and `hotfix`, and for every existing flow that a `fix`,
  `hotfix`, `refactor`, `perf`, or `feat` request alters or relies on.
- **The spec cites its facts.** Every statement in `## Spec` about what exists today
  ends with the ids of its entries, for example "(E3)".
- **Gates.** `/ss-workflow:new-req` approves a request only when no cited entry is
  `to trace` or relied on while `failed`, every cited `inferred` entry is accepted by
  the developer (a `## Q&A` entry and an `Assumption`), and "How to verify" names a
  check for every cited `to test` and `developer-stated` entry. Its cold read also
  re-checks every `verified` entry against the code and reports statements without
  evidence. `/ss-workflow:check-req` re-checks the cited `verified` entries against
  the project branch when it starts or resumes the implementation, and stops at a fact
  that no longer holds. `/ss-workflow:review` checks the `to test` and
  `developer-stated` entries in Verify or in the Review, and passes the Review only
  when each is `verified`, or accepted untested by the developer in `## Q&A`.

## Steps

1. **Root `AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `working-agreement`, which gets the
   item "Evidence, not guesses". Already done when that block contains the words
   "Evidence, not guesses".
2. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` inserts the new block `reqs-evidence` ("Evidence") after
   the block `reqs-spec`, and re-renders `reqs-format`, `reqs-spec`, and
   `reqs-lifecycle`, whose text now names `## Evidence`. Already done when the file
   has the block `reqs-evidence`.
3. **Request files.** Change none. A draft gets `## Evidence` when
   `/ss-workflow:new-req` continues it. A request approved before this version
   (`ready`, `in-progress`, `review`) keeps working without it: the skills skip their
   evidence steps for it and record "not applicable". Tell the developer which drafts
   are affected: the request branches whose request file says `draft`, collected as
   `/ss-workflow:check-req` does in its overview.
