# Migration to 0.16.0

## What changes

- **The Review goes through the manual check one item at a time.** Before:
  `/ss-workflow:review` listed everything to check by hand at once, with how to check
  each item, and waited until the developer had checked all of them and reported back.
  Now: it shows the plan once, then guides the developer through one item at a time.
  For each item it captures what it can observe itself (a serial port, a log file,
  the output of a program or a command that it runs), asks the developer only for the
  actions and observations that it cannot make (a screen, an LED, a button, a cable),
  judges the item from both, and records the result in `## Notes` with a commit before
  the next item. The result says what the agent observed and what the developer
  reported. When an item fails, it asks whether to diagnose and fix it now, to record
  it and decide at the end, or to stop the review. The decisions (behavior changes,
  workspace files, deviations, findings, assumptions) follow one at a time after the
  checks.
- **The Review result is written while the Review runs.** `## Notes` gets one block
  `### Review (yyyy-MM-dd, in progress)` with one entry per item and a `Left:` line.
  A paused review continues with the first item in `Left:`. The outcome of the
  Review removes `, in progress` from the heading.
- **A check by hand says how its result is observed.** "How to verify" in the spec
  (`/ss-workflow:new-req`) and "Review by hand" in the implementation summary
  (`/ss-workflow:check-req`) name, for each check by hand, the steps, the expected
  result, what the agent observes (the source and the expected lines or values), and
  what only the developer sees or does. The cold read of the spec reports a check by
  hand without them. The lead review of `/ss-workflow:check-req` names it as a remark,
  and the implementation adds it to "Review by hand".

## Steps

1. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the block `reqs-spec`. Already done when the
   block `reqs-spec` contains "Each check by hand names its steps, its expected
   result, and how the result is observed".
2. **Request files and branches.** Change none. A request that is already approved
   keeps its "How to verify", and a request in review keeps its implementation
   summary: the Review finds the sources to observe from the code and the project's
   docs. A request whose Review is open keeps its `### Review` entries; the next run
   of `/ss-workflow:review` starts a block `### Review (yyyy-MM-dd, in progress)` for
   the items that have no result yet.
