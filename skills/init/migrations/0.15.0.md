# Migration to 0.15.0

## What changes

- **Every part of a split is kept as a draft at once.** Before: when
  `/ss-workflow:new-req` split an input into several requests, it opened a branch and
  wrote a request file for the first part only, recorded the split in `## Q&A` of that
  request, and left the other parts to a later run that the developer had to start
  with their part of the text. Those parts were kept only in the conversation, and
  were easily lost. Now: when the developer confirms the split, `/ss-workflow:new-req`
  reserves one id per part, and creates a draft for every part right away, each on its
  own request branch, then discusses the first one. A draft that is not discussed yet
  has the line `Split from: REQ-<id>, part <n> of <count>` and its part of the
  developer's words in `## Original`, only a `Depends on:` line (when it needs another
  part) in `## Spec`, and the split, with the table of all parts and their ids, as
  `Q1` in `## Q&A`. A split during the discussion creates the drafts of the parts that
  move out in the same way.
- **The drafts that wait are listed.** `/ss-workflow:new-req` without arguments and
  the overview of `/ss-workflow:check-req` mark such a draft as "not discussed yet",
  with the request it was split from and its `Depends on:`.
  `/ss-workflow:new-req REQ-<id>` continues it like any other draft.

## Steps

1. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of
   `references/upgrade.md` re-renders the blocks `reqs-size` and `reqs-lifecycle`.
   Already done when the block `reqs-size` contains "Every part is kept at once".
2. **Request files and branches.** Change none. A request that was split before this
   version keeps its split entry in `## Q&A`: show the developer the parts in that
   table that have no request yet only when they continue that request, and offer to
   create their drafts then (Step 4a of `/ss-workflow:new-req`).
