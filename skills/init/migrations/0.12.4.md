# Migration to 0.12.4

## What changes

- **A new result value, `not applicable`.** Before: every check in a result was
  `passed`, `failed`, `did not run`, or `not configured`, although some skills
  already wrote "not applicable", for example for the build of a request that
  changes workspace files only. Now: `not applicable`, with the reason, is the fifth
  value, for a check that does not exist for the request. "Results and behavior
  changes" in `reqs/AGENTS.md` lists it.
- **A hotfix states its versions in "Scope".** Before: the spec of a hotfix named
  the released version and the hotfix version somewhere in its text. Now: the first
  line of its "Scope" part is `Hotfix: <name> v<released version> → v<hotfix
  version>`, and `/ss-workflow:check-req` reads the hotfix version from it. A hotfix
  spec written before this version keeps working: check-req finds the version in its
  text, or asks.
- **A request that goes back to `ready` keeps its project branches.** Before: a
  project branch with commits was kept, but the next start treated it as someone
  else's branch and picked a new name. Now: `project-branch` keeps naming it, and the
  next start reuses it.
- **Direct commits on `develop` are listed.** "Branching model" in the root
  `AGENTS.md` names the only commits that are made on `develop` without a request
  branch: a gitlink that is behind, the gitlink of an alpha or beta version, the
  release merge's updates, and the commits of `/ss-workflow:init`.
- **Smaller corrections in the rules:** `remote-cli` is defined in "Remote and
  pushing"; a hotfix's project branch is `hotfix/v<version>`; the code of a spec
  discussion is read at `<project develop-ref>`; the lifecycle names every skill that
  sets a status; the comment of `## Notes` names the code review.

2. **`reqs/AGENTS.md`.** Nothing to do outside the managed blocks: section 3 of

   `reqs-evidence`, `reqs-results`, and `reqs-lifecycle`. Already done when the block
   `reqs-results` names `not applicable`.
3. **Request files and branches.** Change none. A hotfix that is already started
   keeps its spec as it is.
